# 클라우드 구축 자료

Google Cloud에 위험지도 서비스를 올리고, RSU(Jetson)·SUMO 데이터를 저장·집계해
지도로 보여주기까지의 작업 자료입니다. 클라우드·웹 담당자가 보는 문서입니다.

프로젝트 배경·하드웨어 설명은 `docs/인수인계/`에서 다루므로 여기서는 반복하지 않습니다.

## 핵심 요약

- **서버는 안전 기능이 아니다**
  실시간 경고(지팡이 진동)는 차량↔지팡이 직접 통신과 Jetson 판정으로 현장에서 끝나며
  서버를 왕복하지 않습니다. 클라우드가 멈춰도 보행자 안전 기능은 정상 작동합니다.
  서버의 역할은 **기록 · 통계 · 시각화**입니다.

- **파일과 표의 역할을 나눈다**
  판단 기준은 "이 데이터를 지도 화면이 직접 읽는가?" — 예면 Cloud SQL, 아니면 Cloud Storage.
  `master_dataset.csv`(7.9만 행)는 지도가 읽지 않으므로 버킷 보관만,
  `zone_definition.csv`(4행)는 지도가 매번 읽으므로 DB에 넣습니다. **크기가 아니라 용도로 결정합니다.**

- **지도는 3종을 만든다**
  실측(`source=live`) · 시뮬(`source=sumo`) · 종합(`source=combined`).
  종합 등급은 합산이 아니라 `GREATEST(live_grade, sumo_grade)`로 계산합니다.
  그냥 합치면 SUMO 수만 건에 실측 몇 건이 묻히기 때문이며,
  이는 시스템이 이미 쓰는 안전 우선 `max` 융합 원칙과 같은 방식입니다.

- **중복 방지가 데이터 신뢰도를 좌우한다**
  `events.event_uid` UNIQUE로 재전송 중복을, `ingest_log.gcs_uri` UNIQUE로 파일 재적재를 막습니다.
  둘 중 하나라도 없으면 통계가 조용히 부풀려집니다.
