# 2026-06-25 작업 정리

팀원이 돌아왔을 때 오늘 한 작업과 판단 과정을 빠르게 따라올 수 있도록 정리한 문서입니다.

## 오늘의 핵심 결론

차량 ESP32가 ESP-NOW로 데이터를 뿌리고, 별도 수신용 ESP32가 그 무선 패킷을 받아 Jetson으로 넘기는 흐름을 확인했다.

현재 검증된 흐름:

```text
차량 ESP32
  -- ESP-NOW 무선 -->
깡통/RSU 브리지 ESP32
  -- USB Serial -->
Jetson
```

Jetson 터미널에서 차량 JSON이 계속 찍히는 것까지 확인했다. 즉, 차량에서 무선으로 뿌린 데이터가 RSU 역할 ESP를 거쳐 Jetson까지 들어오는 것은 성공했다.

## 왜 깡통 ESP32가 필요한가

Jetson은 ESP-NOW를 직접 수신할 수 없다. ESP-NOW는 ESP32끼리 쓰는 무선 통신이기 때문이다.

그래서 프로토타입에서는 실제 RSU 안에 들어있는 무선 수신 모듈 역할을 깡통 ESP32가 대신한다.

발표 때 설명할 구조:

```text
실제 RSU 한 박스
┌──────────────┐
│ PC5 수신모듈  │  ← 같은 역할 →  깡통/RSU ESP32
│ 컴퓨팅 보드   │  ← 같은 역할 →  Jetson
└──────────────┘
```

정리하면, Jetson 옆에 ESP32를 하나 더 붙이는 것은 한계라기보다 실제 RSU의 내장 무선 수신부를 프로토타입 부품으로 분리 구현한 것이다.

발표 방어 문장:

> ESP-NOW를 Jetson이 직접 못 받는 것은 ESP-NOW의 특성 때문이며, 실제 PC5 RSU에서는 PC5 수신 모듈이 내장되어 있어 발생하지 않는 문제다. 본 프로토타입은 PC5 장비 대신 ESP-NOW를 사용했기 때문에, 실제 RSU의 내장 무선 모듈을 수신 ESP32로 대체하여 동일한 구조를 재현했다.

## 오늘 만든 코드

### 1. 차량 ESP 단독 테스트 코드

파일:

```text
arduino/07_vehicle_jetson_uart_probe/07_vehicle_jetson_uart_probe.ino
```

역할:

- 차량 상태 JSON을 10Hz로 생성
- USB Serial Monitor에 출력
- ESP-NOW broadcast 송신
- Jetson UART 테스트도 가능하도록 작성

시리얼 모니터에서 확인된 예시:

```json
{"type":"vehicle","node_id":2882630492,"seq":8034,"gps_valid":1,"lat":37.000000,"lng":127.013779,"speed_mps":1.506,"heading_deg":90.00,"tx_ms":813359,"espnow":"ok"}
```

의미:

- `seq`가 계속 증가하므로 차량 ESP가 주기적으로 송신 중
- `gps_valid:1`은 현재 가상 GPS 데이터 사용 중이라는 뜻
- `lat`, `lng`, `speed_mps`, `heading_deg`가 Jetson 계산에 들어갈 핵심 값
- `espnow:"ok"`는 ESP-NOW 송신 함수 호출 성공

### 2. RSU/깡통 ESP 브리지 코드

파일:

```text
arduino/08_rsu_espnow_jetson_bridge/08_rsu_espnow_jetson_bridge.ino
```

역할:

- ESP-NOW 수신
- 받은 차량 패킷을 JSON 한 줄로 USB Serial 출력
- Jetson이 `{"risk":2}` 같은 risk를 보내면 읽음
- 읽은 risk를 차량 ESP로 ESP-NOW 회신

이 코드 하나에 "받기"와 "다시 보내기"가 모두 들어 있다. 따라서 깡통 ESP에는 이 파일 하나만 업로드하면 된다.

검증된 Jetson 출력 예시:

```json
{"type":"vehicle","node_id":2882630492,"seq":7399,"gps_valid":1,"lat":37.000000,"lng":127.014008,"speed_mps":1.662,"heading_deg":90.00,"tx_ms":749182,"rx_ms":756920,"recv_count":7400,"lost_count":0,"rssi":-16,"src_mac":"1C:C3:AB:D1:73:5C"}
{"type":"rsu_reply","node_id":2882630492,"seq":7399,"risk":0,"espnow":"ok"}
```

의미:

- `type:"vehicle"`: RSU 브리지 ESP가 차량 패킷을 무선으로 받음
- `recv_count` 증가: 계속 수신 중
- `lost_count:0`: 현재 테스트 환경에서는 유실 없음
- `rssi:-15~-16`: 가까운 거리라 신호가 매우 강함
- `src_mac`: 차량 ESP MAC을 자동 획득
- `type:"rsu_reply"`와 `espnow:"ok"`: RSU 브리지 ESP가 차량으로 답장 송신 성공

## 권한 문제와 해결

Jetson에서 처음 `/dev/ttyUSB0`를 열 때 아래 에러가 났다.

```text
Permission denied: '/dev/ttyUSB0'
```

이것은 포트 인식 실패가 아니라 Linux 사용자 권한 문제다.

해결 방법:

```bash
sudo usermod -aG dialout $USER
sudo reboot
```

바로 확인만 할 때는 `sudo python3 ...`로 실행했다.

## Jetson에서 간단 수신 확인 코드

Jetson의 `~/v2x/read_bridge.py`에 아래 코드로 확인했다.

```python
import serial
import time

PORT = "/dev/ttyUSB0"
BAUD = 115200

while True:
    try:
        ser = serial.Serial(PORT, BAUD, timeout=1)
        print(f"opened {PORT} at {BAUD}")
        break
    except PermissionError:
        print("permission denied. Run with sudo or add user to dialout.")
        raise
    except Exception as e:
        print(f"waiting for {PORT}: {e}")
        time.sleep(1)

while True:
    line = ser.readline().decode(errors="replace").strip()
    if line:
        print(line)
```

실행:

```bash
sudo python3 read_bridge.py
```
