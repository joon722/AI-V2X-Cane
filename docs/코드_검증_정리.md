## 수행계획서 기준 핵심 기능

1. ESP32 기반 V2X 통신
   - ESP-NOW로 송신기와 수신기 간 저지연 패킷 송수신
   - 송신기 GPS/IMU 센서값을 수신기로 전달

2. GPS/IMU 센서 통합
   - ICM-20948 IMU: SDA GPIO21, SCL GPIO22
   - Neo-6M GPS: GPS TX -> ESP32 GPIO16, GPS RX -> ESP32 GPIO17
   - 실내 GPS 미수신 상황에서도 `gps_valid`, `charsProcessed` 등으로 UART 동작 확인

3. Jetson 또는 Python/AI 연동
   - ESP32 수신 데이터를 Jetson으로 전달
   - CSV replay 또는 실제 ESP32 송신 모드에서 `risk` 0-3 출력
   - 위험도 결과를 하드웨어 피드백으로 연결

4. 진동/음성 기반 멀티모달 피드백
   - 위험도 0/1/2/3에 따라 진동과 음성이 다르게 동작
   - 5.17 계획서 기준으로 DFPlayer Mini, 진동모터, 스피커 확인 필요

## 현재 코드 확인 결과

### 들어가 있는 기능

- `arduino/5.10 송신기 코드`
  - GPS, ICM-20948 IMU, ESP-NOW 송신 구조가 들어 있음
  - 송신 주기 100ms 설정
  - `v2x_message_t` 구조체에 GPS, 속도, 방향, 가속도, 자이로, 시퀀스 번호 포함
  - 테스트용 위험도 판단 함수 `decideRiskForTest()` 포함

- `arduino/5.10 수신기 코드`
  - ESP-NOW 수신 코드가 들어 있음
  - 수신 패킷 크기 검증 포함
  - 수신 데이터를 Jetson UART로 JSON 한 줄씩 전달
  - `risk_level`에 따라 진동모터와 부저를 제어

- `arduino/박중선`
  - IMU + GPS 단독 통합 읽기 테스트 코드로 보임

- `arduino/5.3일 강현준 수신기 송신기 연결`
  - 초기 ESP-NOW 송수신 테스트 코드로 보임
  - 한 파일 안에 Receiver와 Sender 코드가 같이 들어 있어 실제 업로드용으로는 분리 필요

### 빠져 있거나 약한 부분

1. DFPlayer Mini 음성 재생 코드가 현재 저장소에서 확인되지 않음
   - 검색 대상: `DFPlayer`, `speaker`, `audio`, `mp3`
   - 현재 수신기 코드는 "음성"이 아니라 Active LOW 부저 제어 중심
   - 수행계획서의 "음성 안내", "DFPlayer", "스피커" 요구와는 아직 불일치
   - 사용자가 제공한 `SOUND.ino`도 DFPlayer 음성 재생이 아니라 UDP 기반 부저/진동 패턴 코드임

2. 위험도 3이 송신기 테스트 로직에서 사실상 생성되지 않음
   - `decideRiskForTest()`는 `RISK_WARNING(2)`, `RISK_CAUTION(1)`, `RISK_SAFE(0)`만 반환
   - 수신기는 3 이상을 danger처럼 처리하지만, 송신기가 3을 보내는 경로가 없음

3. Arduino 파일들이 `.ino` 확장자가 아님
   - 현재 파일명 예: `arduino/5.10 송신기 코드`
   - Arduino IDE/arduino-cli 기준으로는 스케치 폴더와 `.ino` 파일 형태가 필요
   - 예: `arduino/sender_20260510/sender_20260510.ino`

4. `5.3일 강현준 수신기 송신기 연결`은 한 파일에 두 개의 Arduino 스케치가 섞여 있음
   - `setup()`/`loop()`가 두 벌이라 그대로는 컴파일 불가
   - 테스트 기록용으로 보관하거나 `receiver_test.ino`, `sender_test.ino`로 분리 필요

5. AI/Python 파트가 거의 비어 있음
   - `AI_Model/AI.txt`: 설명 수준
   - `python/파이썬 파일.txt`: 비어 있음
   - `python/VKDLTJS.txt`: 설명 수준
   - 수행계획서의 CSV replay, risk 계산, 시각화, Jetson 처리 코드가 현재 저장소에는 충분히 없음

6. 컴파일 검증은 아직 못 함
   - 현재 PC/Codex 환경에서 `arduino-cli`가 설치되어 있지 않음
   - 실제 검증은 Arduino IDE 또는 arduino-cli 설치 후 ESP32 보드 패키지/라이브러리 설치가 필요

## 진동/소리 관련 상태

현재 들어간 것:

- 진동모터 핀: GPIO26
- 부저 핀: GPIO25
- 부저 Active LOW 가정
- 모터 Active HIGH 가정
- 위험도별 동작:
  - risk 0: 모터 OFF, 부저 OFF
  - risk 1: 모터 ON, 부저 OFF
  - risk 2: 모터 ON, 짧은 부저
  - risk 3 이상: 모터 ON, 짧은 부저

부족한 것:

- DFPlayer Mini 라이브러리/시리얼 제어 없음
- `0001.mp3`, `0002.mp3` 같은 음성 트랙 재생 로직 없음
- risk 2와 risk 3의 피드백 차이가 거의 없음
- 진동 패턴이 세기/주기별로 차등화되어 있지 않음

추가 확인한 `SOUND.ino` 상태:

- Jetson에서 Wi-Fi UDP로 `{"risk":0}`, `{"risk":1}`, `{"risk":2}`, `{"risk":3}` 명령을 받는 구조
- 진동 핀: GPIO25
- 부저 핀: GPIO27
- risk 1: 약한 진동
- risk 2: 약한 진동 + 느린 부저
- risk 3: 강한 진동 + 3연속 부저
- 원본에는 Wi-Fi SSID/비밀번호가 직접 들어 있어 GitHub 업로드 전 분리 필요
- 정리본은 `arduino/sound_udp_receiver/`에 추가함

주의:

- 기존 `5.10 수신기 코드`는 ESP-NOW 수신 + Jetson UART 송신 + GPIO25/26 액추에이터 제어 구조
- `SOUND.ino`는 Wi-Fi UDP 수신 + GPIO25/27 액추에이터 제어 구조
- 두 코드는 핀 번호와 데이터 흐름이 다르므로 그대로 합치면 충돌 가능성이 있음
- 현재 수행계획서 흐름이 "Jetson risk 결과를 다시 지팡이에 보내 피드백"이라면 `SOUND.ino` 방식이 더 가까움
