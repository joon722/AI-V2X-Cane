## 전제

- 펌웨어의 V4 로그 키 이름은 바꾸지 않는다.
- Claude는 기존 키를 기준으로 UI에서 선택·정렬·그룹화한다.
- 펌웨어 기본값은 `logmode 0`, 500 ms(2 Hz)이다.
- `logmode 1`이면 기존 V4 전체 진단 키가 다시 들어온다.
- UDP 4211=차량, UDP 4210=지팡이, 명령 UDP 4300은 그대로다.

## 권장 화면

기존의 “수신한 모든 키를 한 Treeview에 삽입”하는 방식 대신 노드별로 아래 순서의 고정 요약 카드를 먼저 보여준다.

1. 위험: `위험`, `RSU위험`, `RSU위험경과ms`
2. GPS: `GPS유효`, `위도`, `경도`, `속도`, `방향`, `GPS위성`, `GPS_HDOP`
3. IMU: `IMU보정`, `IMU정렬`, 차량 `차체방향` / 지팡이 `IMU방향`
4. UWB: `UWB유효`, `UWB보정거리`, `UWB경과ms`, 필요 시 `UWB접근속도`
5. 링크/전원: `RSSI원시`, `RSSI경과ms`, `송신`, `부팅횟수`, `리셋원인`

상태 색상:

- fresh: age 0~1000 ms = 초록
- stale: 1001~3000 ms = 주황
- timeout 또는 음수 = 빨강
- `GPS유효=0`, `UWB유효=0`, `리셋원인=BROWNOUT`은 빨강
- `IMU보정`의 네 숫자가 모두 3이고 `IMU정렬=1`이면 초록

## 화면을 덜 어지럽게 만드는 변경

- 원본 로그 창은 기본 접힘. “원본 로그 보기” 토글로만 펼친다.
- 요약 카드에 없는 값은 “상세 진단” 접이식 영역에 둔다.
- 새 키가 들어와도 요약 카드 순서는 바뀌지 않게 한다.
- 값이 갱신될 때 행 전체를 깜빡이지 말고 값 글자만 갱신한다.
- 기록 파일에는 기존처럼 받은 전체 로그와 전체 키를 보존한다.
- 화면 표시를 숨겨도 CSV 기록은 버리지 않는다.
- 상단에 `운영 모드(logmode 0)` / `상세 모드(logmode 1)` 버튼을 두고 해당 명령을 두 노드에 보낸다.
- `IMU 상태`, `IMU 저장`, `IMU 초기화` 버튼은 각각 `imu`, `imusave`, `imureset`을 보낸다.
- `imualign`은 숫자 입력칸을 둔다.
- UWB 버튼은 기존 `uwb status`, `uwb cal 3`, `uwb reset`을 사용한다.

## V5에서 새로 생긴 로그 값

| 이름 | 단위/형식 | 뜻 | 표시 위치 |
|---|---|---|---|
| `IMU보정` | `S/G/A/M`, 각 0~3 | BNO055 시스템/자이로/가속도/자력계 보정 단계 | IMU 요약 |
| `IMU정렬` | 0 또는 1 | 장착 방향을 실제 방위에 맞춰 저장했는지 | IMU 요약 |

`부팅횟수`, `리셋원인`은 지팡이 V4에 이미 있던 이름이며 V5 차량에도 같은 이름으로 추가됐다. 그 외 기본 요약 키는 V4에 있던 이름을 그대로 재사용한다.

## Wi-Fi UDP 유지 이유

UDP는 화면/기록용 진단 경로이고 위험판정이나 센서 처리 경로가 아니다. V5는 화면 로그를 2 Hz로 낮췄기 때문에 Wi-Fi 브로드캐스트가 BNO055 100 Hz, GPS/UWB 5 Hz, ESP-NOW 10 Hz 성능을 제한하지 않는다. 따라서 평소 뷰어는 UDP를 유지한다.

100 Hz 원시 IMU를 기록하는 별도 실험 모드가 필요해질 때만 USB 유선 시리얼(권장 460800 또는 921600 bps)을 추가한다. TCP/WebSocket으로 바꾸는 것은 재전송 지연과 연결 관리가 생기므로 현재 운영 모니터의 대체안으로는 권장하지 않는다.
