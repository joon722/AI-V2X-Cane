# 실험 계획 — GPS 5Hz 확인 + 안전 하한 검증 + 모델 검증 데이터 확보

작성 2026-08-06 · 목표 실시일 8/17 통합테스트 이전

## 왜 이 실험이 필요한가

지금 세 가지가 확인되지 않은 상태다.

1. **GPS 5Hz 전환이 실제로 반영됐는가.** 배포한 안전 하한 `T_floor = 2.0초`는
   GPS 주기 0.2초를 전제로 계산한 값이다. 1Hz면 필요한 하한이 2.8초가 되어
   전제가 무너진다. 8/5 로그 기준으로는 936ms(1.1Hz)였다.
2. **안전 하한이 실기에서 어떻게 동작하는가.** 시뮬레이션에서는 오경보가
   2.03%에서 3.24%로 늘고 검출이 18/19에서 19/19가 된다. 실기 수치는 없다.
3. **모델 검증에 쓸 표본이 있는가.** 현재 실측 검증은 9스텝뿐이다. 8/5 로그에는
   차량 속도 3 m/s 이상 구간의 접촉 위험이 **0건**이었다.
4. **위치 산포 σ가 실제로 얼마인가.** 지금까지 2.5m로 가정해 왔으나 실측한 적이
   없다. `ROADSIDE_ALARM.md` 5~6절에서 **σ가 시스템 전체 성능을 지배하는 변수**로
   확인되었다 — 적시경보가 σ 4.0m에서 60.1%, 1.0m에서 88.2%로 갈린다. 이 값
   하나가 이후 판정 구조 결정을 좌우한다.

**한 번의 실험으로 넷을 모두 확인할 수 있다.**

## 목표 수치

| 항목 | 목표 | 확인 방법 |
|---|---|---|
| **위치 산포 σ** | **측정값 확보** (가정 2.5m 검증) | 정지 5분 로깅 → 표준편차 |
| GPS 갱신 주기 | 200ms 부근 (5Hz) | `verify_experiment.py` 1번 항목 |
| 차량 속도 | **3 m/s(10.8 km/h) 이상** 구간 확보 | 3번 항목 |
| 접촉 위험 이벤트 | **30건 이상** (2m 이내 접근) | 3번 항목 |
| 접근 각도 | 정면 / 측면 / 후방 고르게 | 시나리오 배분 |
| **오경보 실측** | 시나리오 D에서 발동 건수 | `reason=safety_floor` 집계 |

σ 측정을 첫 줄에 둔 이유는 **가장 싸고 가장 결정적이기 때문이다.** 노드를 한 자리에
두고 5분 로깅하면 끝나며, 그 값이 `ROADSIDE_ALARM.md` 5절 표의 어느 행에 떨어지는지에
따라 이후 작업이 갈린다.

**측면 접근을 반드시 포함할 것.** 시뮬레이션에서 측면 위험의 53%가 TTC 무한대
상태였다. 규칙이 놓치고 모델이 잡는 구간이 여기라, 실측으로 확인해야 할 핵심이다.

## 안전 확보 — 사람을 위험에 두지 않는다

**보행자 노드를 사람이 들지 않는다.** 차량을 사람에게 2m까지 접근시키는 실험은
해서는 안 된다. 대신:

- 지팡이 노드를 **삼각대, 카트, 또는 콘 위에** 고정한다 (지면 1.0~1.2m 높이,
  실제 착용 높이와 맞춤)
- 조작자는 **차량 경로 밖**에서 대기한다
- "보행자 이동" 시나리오가 필요하면 노드를 실은 카트를 **줄로 끌어** 움직인다

이렇게 하면 위험 데이터를 안전하게 만들 수 있다. GPS·통신·판정 로직 입장에서는
노드가 사람 손에 있든 삼각대에 있든 동일하다.

**주의:** 차량 노드를 실은 차량은 3 m/s 이상으로 움직여야 하므로, 통행이 없는
공터나 폐쇄된 구역에서 진행한다. 자전거나 전동 킥보드로 대체해도 목표 속도는
충족된다(3~7 m/s).

## 실험 절차

### 0단계 — 어떤 코드와 모델이 도는지 확정한다 (실험 전 필수)

**이것을 하지 않으면 이후 데이터 전부가 "어느 버전의 숫자인지" 알 수 없게 된다.**
8/5 로그가 정확히 그 상태다 — 실차 연결은 증명하지만 현행 코드를 증명하지 못한다
(당시 TTC 0.82초에 레벨 2가 나갔는데, 현행 안전 하한이라면 레벨 3이어야 한다).

**확인된 문제.** 같은 이름의 모델 파일이 두 곳에 있고 내용이 다르다.

| 파일 | 트리 | threshold | 30m 정지 차량 |
|---|---|---|---|
| `risk_model.json` (젯슨이 로드) | 91 | 0.140067 | **레벨 2 경보** |
| `ttc_study/risk_model.json` | 109 | 0.050328 | 침묵 |

정지한 차량이 30m 밖에 있고 접근하지도 않는데 배포 모델이 경보를 낸다.
`test_model_gate.DeployedModelSanityTest`가 이것을 고정해 두었다(현재 실패 상태).

**절차**

1. **먼저 지금 무엇이 도는지 확인한다.**
   ```
   grep -n "T_FLOOR_TTC_S" ~/v2x/03_jetson/step7_risk.py     # 2.0 이 나와야 함
   md5sum ~/v2x/03_jetson/risk_model.json                    # 기록해 둘 것
   ```
   2026-08-07 확인 결과: 하한은 정상 배포되어 있고(140행), 모델은
   `3b5478beb6e68cf859feb89f042208fb`(735,295바이트)로 **위 표의 젯슨 배포본**이다.

2. **규칙만으로 한 세션** — 이것이 기준선이다.
   ```
   sudo systemctl stop v2x-risk-engine
   V2X_NO_MODEL=1 ~/v2x/03_jetson/deploy/run_v2x_risk_engine.sh
   ```
   시작 줄에 `MODEL=off`가 찍히는지 확인한다. 끝내려면 Ctrl+C.

3. **모델 켠 세션은 따로.**
   ```
   sudo systemctl start v2x-risk-engine
   ```

4. 두 세션을 같은 시나리오로 돌려 비교한다(섀도우 비교).

`V2X_NO_MODEL` 환경변수는 2026-08-07에 래퍼에 추가했다. 주지 않으면 기존과
동일하게 모델을 싣는다.

**왜 규칙만 세션이 먼저인가.** 모델이 정지 차량에 반응하는 상태이므로, 모델을 켠
채로만 찍으면 시나리오 D의 경보가 **안전 하한 때문인지 모델 오작동 때문인지
구분할 수 없다.** 기준선이 있어야 차이를 모델 탓으로 돌릴 수 있다.

### 사전 확인 — GPS 수신기 설정 (실험 전, 코드 아님)

σ가 지배 변수인데(`ROADSIDE_ALARM.md` 6절), 부품을 바꾸지 않고 설정만으로 개선될
여지가 남아 있을 수 있다. **실험 전에 확인해야 실측값 자체가 좋아진다.**

| 확인 항목 | 내용 |
|---|---|
| SBAS 활성화 | NEO-6M도 지원한다. 기본으로 꺼져 있을 수 있다 |
| dynamic platform model | 기본값 Portable. Pedestrian으로 두면 보행 속도에 맞춰진다 |
| 안테나·배치 | 기본 세라믹 패치인지, 몸에 가려지는 위치인지 |

u-center로 현재 설정을 읽고 위성 수·HDOP를 비교하는 것이 가장 빠르다.
**국내 SBAS 수신 가능 여부와 실제 개선 폭은 확인되지 않았다** — 설정을 바꿨다면
바꾸기 전후로 각각 σ를 재서 효과를 확인한다.

### 준비

1. **차량을 먼저 켠다.** 지팡이 펌웨어는 차량이 만드는 `V2X-LOG` AP에 20초 안에
   접속하지 못하면 재부팅을 반복한다. 순서를 지키지 않으면 지팡이가 ESP-NOW를
   시작조차 못 한다.
2. 브리지 상태 확인: `python3 scripts/check_bridge.py`
   → `bridge_boot version:3` 확인 (v3 프로토콜, 36바이트)
3. 링크 상태 확인: `python3 scripts/watch_link.py` → `READY` 확인
4. 젯슨 엔진 재시작으로 새 로그 시작:
   `sudo systemctl restart v2x-risk-engine`

### 본 실험 — 시나리오 3종 × 10회

각 회차 사이에 5초 이상 간격을 둔다(궤적이 섞이지 않게).

| # | 시나리오 | 접근 | 목표 통과 거리 | 반복 |
|---|---|---|---|---|
| A | 정면 접근 | 노드를 향해 직진 | 0.5~2 m | 10 |
| B | **측면 통과** | 노드 옆을 가로질러 통과 | 1~2 m | 10 |
| C | 사선 접근 | 45도 방향에서 접근 | 0.5~2 m | 10 |
| D | **스쳐 지나감** | 노드 옆을 나란히 통과 | **3 / 5 / 7 m** | 각 5 |

**B와 D가 가장 중요하다.** B는 TTC로 잡히지 않는 위험이 나오는 자리이고,
D는 **울리지 않아야 할 때 조용한지**를 보는 유일한 시나리오다.

**D가 왜 필수인가.** A·B·C는 전부 "위험을 잡는가"만 본다. 그런데 계산상 인도를
나란히 걷는 상황에서 **횡방향 7m가 떨어져 있어도 안전 하한이 레벨 3을 낸다**
(`ROADSIDE_ALARM.md` 2절). 팀에서 나온 "인도 걷는데 옆 차 때문에 울리나"라는
질문에 답하려면 D를 찍어야 한다. 통과 거리를 3·5·7m로 나누는 이유는 어느
지점부터 조용해지는지를 보기 위해서다.

가능하면 D는 **노드를 정지시키지 말고 카트로 끌어 평행 이동**시킨다. 팀이 걱정한
상황은 보행자도 움직이는 경우이고, 정지 상태에서는 접근 기하가 달라진다.

여유가 있으면 추가:

| # | 시나리오 | 목적 |
|---|---|---|
| E | 접근하다 정지 | 하한이 잘못 발동하는지 확인 |

### 최우선 측정 — 위치 산포 σ (10분)

**본 실험보다 먼저 한다.** 가장 싸고 가장 결정적이다.

1. 지팡이 노드를 한 자리에 고정한다 (실제 착용 높이 1.0~1.2m)
2. **움직이지 않은 채 5분 로깅**한다
3. 차량 노드도 다른 자리에 고정해 같이 5분 로깅한다 (두 노드의 σ가 다를 수 있다)

**집계.** 좌표를 미터로 바꿔 동/북 성분의 표준편차를 낸다. 위치는 고정이므로
흩어진 정도가 곧 σ다.

| 나온 값 | 의미 (`ROADSIDE_ALARM.md` 5절) |
|---|---|
| σ ≤ 1.5 m | 하한 조건화가 사실상 공짜. 오경보 −1.1%p, 놓침 없음 |
| σ 2.0~2.5 m | 조건화는 놓침 2~4개를 사는 거래. 보류 권고 |
| σ ≥ 4.0 m | 조건화 논외. **측위 개선이 최우선 과제가 된다** |

**개활지와 건물 사이 두 곳에서 각각 잰다.** CEP 2.5m는 개활지 사양이고, 실제
운용은 건물 사이에서 이루어진다. 두 값의 차이가 도심 성능 저하의 크기다.

### 추가 측정 — 차폐 RSSI A/B (30분, 차량 불필요)

**목적.** "운전자가 보지 못하는 곳"을 감지할 수 있는지 확인한다. 전파가 벽에
막히면 감쇠하므로, 벽을 모델링하지 않고도 차폐 여부를 읽을 수 있는지 보는 것이다.
근거는 `ROADSIDE_ALARM.md` 8절.

**절차 — 같은 자리, 같은 세션에서 차폐물만 바꾼다.**

1. 두 노드를 10m 간격으로 고정한다 (거리는 끝까지 바꾸지 않는다)
2. 30초 LOS(가림 없음) → 30초 차폐 → 30초 LOS 순으로 번갈아 로깅한다
3. 차폐물 3종을 각각 반복한다: **벽(건물 모서리) / 주차 차량 / 사람 몸**

**교대로 찍는 것이 이 측정의 전부다.** 서로 다른 날의 로그를 비교하면 안 된다 —
기존 `rssi_1m.log`(중앙값 −64)와 `rssi_3m.log`(−39)가 3배 먼 쪽이 25 dB 강하게
나온 것이 그 실패 사례다. 송신 조건이 달랐기 때문이다.

**기록할 것**

| 항목 | 판정 |
|---|---|
| LOS 구간 rssi 중앙값 | 기준선 |
| 차폐 구간 rssi 중앙값 | 차이가 10 dB 이상이면 판별 가능 |
| 각 구간의 산포 | 기존 로그 기준 4~7 dB. 이보다 크면 신호가 묻힌다 |
| `lost_count` 증가율 | RSSI보다 나은 지표일 수 있다 |

**판정 기준.** 차폐 감쇠가 산포의 2배 이상이면 NLOS 게이트를 만들 근거가 된다.
아니면 이 방향은 접고 기록만 남긴다.

### 추가 측정 — 눈가리개 진동 인지 (20분)

**왜 필요한가.** 안전 하한 2.0초의 항 중 "정지 동작 1.2초"는 일반 보행자의 급정지
실험 문헌에서 빌려온 값이다. 시각장애인이 진동 경보를 받고 멈추기까지의 시간을
직접 잰 연구를 찾지 못했기 때문이다. 당사자 섭외가 어렵다면, **시각을 차단하고
직접 재는 것**이 현실적인 대체다. 완벽하지 않지만 문헌 대용값보다는 우리 시스템에
가깝다.

**절차** — 차량 실험과 별개로, 지팡이 노드를 손에 들고 진행한다.

1. 측정자가 안대를 착용하고 평소 보행 속도로 직진한다
2. 보조자가 임의 시점에 젯슨에서 레벨 3을 강제 송신한다
   ```
   echo '{"target_id":0,"risk":3}' > /dev/v2x-rsu
   ```
   (또는 차량 노드를 접근시켜 자연스럽게 발동시킨다)
3. **진동이 온 순간부터 완전히 멈출 때까지**를 스톱워치로 잰다
4. 10회 반복, 측정자를 바꿔 2명 이상

**기록할 것**

| 항목 | 왜 |
|---|---|
| 인지~정지 시간 (10회) | T_floor의 정지 항을 우리 측정값으로 대체 |
| 진동을 놓친 횟수 | 세기가 충분한지 |
| 주관적 코멘트 (세기·패턴) | 발표에서 인용 |

**결과 반영.** 측정 중앙값이 1.2초와 크게 다르면 `step7_risk.T_FLOOR_TTC_S`를
다시 계산해야 한다. `safety_floor.py`의 `stopping_s` 인자를 바꿔 넣으면 새 하한이
나오고, 그 값으로 `evaluate.py`를 다시 돌려 성능 영향을 확인한다.

## 실험 후 검증

PC로 로그를 가져와 한 번에 확인한다.

```bash
python verify_experiment.py --log ../logs/exp_8.X_5Hz검증_raw.log
```

출력 네 항목이 각각 다음을 답한다.

1. **GPS 갱신 주기** — 200ms 부근이면 5Hz 확인. 900ms대면 전환이 반영되지 않은 것.
2. **안전 하한 발동** — 레벨 3 송신 건수. 정확한 판정은 CSV에서
   `ttc_s <= 2.0 && risk_level == 3`인 행을 세면 된다.
3. **표본 수량** — 고속 접촉 이벤트가 30건 이상이면 모델 검증 가능.
4. **섀도우 비교** — 같은 궤적에서 모델과 규칙이 각각 언제 울렸는지. 모델만
   울린 구간이 실제로 위험했는지 육안으로 확인할 수 있다.

## 실험이 실패로 판정되는 경우와 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| GPS가 900ms대 | 5Hz 설정이 반영 안 됨 | 펌웨어의 UBX-CFG-RATE 확인. 보드레이트 9600에서 GGA+RMC만 남겼는지 확인 |
| 지팡이 레코드 없음 | 차량 AP 미기동 또는 브리지 버전 불일치 | 차량 먼저 켜기, `check_bridge.py`로 v3 확인 |
| 브리지 무응답 | 젯슨 USB 전류 부족(브라운아웃) | 다른 포트, 굵은 케이블, 전원공급형 허브 |
| 고속 위험 0건 | 차량이 너무 느리거나 멀리 지나감 | 목표 통과 거리 2m 이내를 지켰는지 확인 |
| 오경보가 과하게 많음 | 안전 하한(TTC 2.0s) 발동 | CSV에서 `reason` 확인. 의도된 동작이며 검출률과 트레이드오프다 |

## 영상을 반드시 찍을 것

시나리오 B(측면 통과) 중 **한 번은 영상으로 남긴다.** 화면에 TTC가 큰 값인데
지팡이가 진동하는 장면이면 된다.

이 5초가 발표 전체보다 강하다. "TTC 임계값으로는 원리적으로 잡히지 않는 위험이
있다"는 이 연구의 핵심 주장을, 말 대신 한 장면으로 보여주기 때문이다. 측면 위험의
53%가 그 상태였다는 시뮬레이션 수치도 이 영상이 있어야 실감이 난다.

가능하면 두 화면을 나란히 담는다 — 젯슨 콘솔(TTC 값과 [TX] 출력)과 지팡이(진동).

## 이 실험으로 답할 수 있게 되는 것

- **위치 산포 σ가 얼마인가 — 이후 판정 구조 결정의 전제**
- 안전 하한 2.0초의 전제(GPS 5Hz)가 실제로 충족되는가
- 실기 오경보율이 시뮬레이션 예측(3.24%)과 비슷한가
- **인도를 나란히 걸을 때 실제로 몇 번 울리는가, 몇 미터부터 조용해지는가** (D)
- 모델이 시뮬레이션에서 보인 우위(+18.9%p)가 실측에서도 관찰되는가
  (단, 이 값은 σ=2.5 조건의 것이다 — `ROADSIDE_ALARM.md` 10절)
- TTC가 무한대인 측면 위험을 모델이 실제로 잡는가 (연구의 핵심 주장)
- **차폐를 RSSI로 감지할 수 있는가** (NLOS 게이트의 전제)
- 진동 경보를 받고 멈추기까지 실제로 몇 초가 걸리는가 (T_floor 재산출)
