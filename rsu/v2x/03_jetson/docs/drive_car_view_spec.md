# 차량 운전석 1인칭 뷰 — `drive.html` 재구현 지침서

**받는 사람:** 박채린
**작성:** 현준 · 2026-08-12
**대상 파일:** `v2x-server/static/drive.html`

---

## 0. 한 줄 요약

지금 `drive.html`(지팡이 시점 + 가짜 목업)을 **차량 운전석 1인칭 시점 + 젯슨 실데이터 연동**으로 다시 만든다.

---

## 1. 컨셉 — 무엇을 보여주는 화면인가

- 프로젝트 전체의 보호 대상은 **시각장애인(지팡이)** 이다. 그건 그대로다.
- 하지만 **이 화면만큼은 차량 운전자 1인칭 시점**이다. 보여주려는 메시지는:
  > "운전자 눈(카메라)에는 안 보이는 보행자를, V2X가 무선으로 미리 감지한다."
- 즉 **차량이 주인공**이다. 화면의 시점(카메라)이 차량이고, 보행자(지팡이 착용자)는 그 앞에 감지되는 대상이다.
- 지금 화면은 정반대(지팡이가 서서 앞을 보는 보행자 시점)라, **시점을 통째로 뒤집어야 한다.**

---

## 2. 3대 원칙 (헷갈릴 때 판단 기준)

1. **시연 임팩트 우선** — 정확도보다 "한눈에 이해되고 인상적"이 중요하다. 대략적이어도 된다.
2. **실기로 작동** — 자동재생 목업이 아니라, 실제 지팡이+차량을 움직이며 젯슨 실데이터로 돌아가야 한다. 미숙해도 "작동은" 해야 한다.
3. **차량이 시점** — 현재 목업의 지팡이 시점 요소를 전부 걷어내고 차량 1인칭으로.

---

## 3. 데이터 — 어디서 오나

젯슨이 현장 핫스팟에서 직접 HTTP 서버를 띄운다. 화면은 여기를 **폴링**해서 읽는다.

```
GET http://<젯슨IP>:8080/api/state
```

- 현재 핫스팟 IP: `172.20.10.13` (재부팅/핫스팟 재연결 시 바뀜 → 그때 다시 공유)
- 폴링 주기 **250ms** 권장 (판정이 ~1Hz라 더 자주 불러도 같은 값이 온다)
- 데이터가 없을 때도 **HTTP 200**으로 온다 (에러 아님)

### 응답 예시 (차가 앞 15m에서 접근 중일 때)

```json
{
  "t": 1786347767.03, "age_s": 0.27,
  "level": 3, "level_source": "table",
  "reason": "safety_floor", "trusted": true,
  "distance_m": 14.98, "ttc_s": 1.5, "closing_mps": 10.01,
  "dcpa_m": 1.4,
  "rel_east_m": 0.0, "rel_north_m": 14.98,
  "cane": {"lat":37.4963,"lng":126.9575,"heading_deg":0.0,"speed_mps":0.0,"gps_valid":1},
  "veh":  {"speed_mps":8.0,"heading_deg":180.0,"gps_valid":1}
}
```

## 4. 필드 명세

| 필드 | 타입 | 의미 |
|---|---|---|
| `t` | number \| **null** | 측정 시각(epoch 초). **`null`이면 아직 데이터 없음(대기 중)** |
| `age_s` | number \| null | `t`가 얼마나 지났는지(초). **연결 상태 판단용** |
| `level` | int (0~3) | 젯슨 최종 위험등급. 0 안전 / 1 주의 / 2 경고 / 3 위험. **재계산 금지, 그대로 사용** |
| `level_source` | string \| null | `"table"`(규칙) 또는 `"model"`(모델). 화면에 안 써도 됨 |
| `reason` | string \| null | 판정 근거. 화면에 안 써도 됨 |
| `trusted` | bool | GPS 신뢰 여부 |
| `distance_m` | number \| null | 지팡이–차량 거리(m) |
| `ttc_s` | number \| **null** | 충돌까지 시간(초). **접근 중이 아니면 `null`** (9999 같은 큰 수 아님) |
| `closing_mps` | number \| null | 접근 속도. **+ 접근 중 / − 멀어지는 중** |
| `dcpa_m` | number \| null | 최근접 예상 거리(m). 클수록 옆으로 비껴감 |
| `rel_east_m` / `rel_north_m` | number \| null | **지팡이 기준** 차량의 동/북 위치(m). ★좌표 변환의 핵심 입력★ |
| `cane` | object | 지팡이: `{lat, lng, heading_deg, speed_mps, gps_valid}` |
| `veh` | object | 차량: `{speed_mps, heading_deg, gps_valid}` — **lat/lng 없음** |
| `*.gps_valid` | **0 / 1 숫자** | boolean 아님 |

---

## 5. ★핵심★ 좌표 변환 — 차량 시점으로 뒤집기

`rel_east_m` / `rel_north_m`은 **지팡이 기준** 차량 위치다(나침반 방위, 0=북). 우리는 **차량 기준 보행자 위치**가 필요하니 **부호를 뒤집고**, 차량이 향한 방향이 화면 위가 되게 **회전**한다.

```js
// 1) 차량 기준 보행자의 절대 동/북 (부호 반전)
const pe = -rel_east_m;   // 보행자가 차량 기준 동쪽으로 몇 m
const pn = -rel_north_m;  // 북쪽으로 몇 m

// 2) 차량 진행방향(heading)으로 회전 → 운전석 기준 앞/좌우
const vh = (veh.heading_deg ?? lastHeading) * Math.PI / 180;
const forward = pe * Math.sin(vh) + pn * Math.cos(vh);  // + 차 앞 / − 뒤
const right   = pe * Math.cos(vh) - pn * Math.sin(vh);  // + 오른쪽 / − 왼쪽

// 3) 기존 proj(깊이, 좌우) 엔진에 그대로 넣으면 운전석 시점 배치
//    proj(forward, right)
```

**검증(위 예시 JSON):** `veh.heading=180`(남향), `rel_north_m=14.98`(차량이 지팡이보다 북쪽 15m = 지팡이는 차량 정면 남쪽 15m)
→ `forward = +15.0`(정면), `right = 0.0` → 차 정면 15m에 보행자. ✅

### ⚠️ heading fallback (반드시 넣을 것)

`veh.heading_deg`는 차량이 **움직일 때만** 나온다. 신호대기·정지 중이거나 GPS가 순간 끊기면 `null`이거나 값이 튄다.
→ **마지막 유효 heading을 유지(`lastHeading`)** 해라. 안 하면 정지할 때마다 화면이 홱 돌아버린다. (대략적이어도 되니 이 정도 방어면 충분)

## 6. 반드시 지킬 함정 7 (안 지키면 화면이 실제와 어긋남)

1. **`level`을 브라우저에서 재계산하지 마라.** 지금 `levelOf()`가 TTC로 자체 계산하는데, 젯슨은 안전하한(2.8초)으로 판정해서 기준이 다르다. `level` 값을 그대로 써라.
2. **`ttc_s`가 `null`이면 "접근 아님"** → `--` 로 표시. 큰 수(9999)로 오지 않는다.
3. **대기 판별은 `t === null`로.** `level`이 0이어도 데이터가 없는 것일 수 있다(`t:null, level:0, trusted:false`). `level:0`을 "안전"으로 오해하지 마라.
4. **`gps_valid`는 0/1 숫자**(boolean 아님).
5. **`veh`에는 lat/lng가 없다.** 차량은 `rel_east/north` 상대좌표로만 그린다.
6. **`age_s`로 연결 상태를 판단.** 지금 "연결됨 · 10 Hz"가 고정으로 박혀 있는데, `age_s` 기반으로 바꿔라(아래 8번).
7. **목업 보행자들·반대편 차량 제거.** 젯슨은 지팡이 1명 + 차량 1대만 안다. 나머지는 전부 가짜다.

---

## 7. 화면 구성 (제안 — 세부 디자인은 재량)

- **운전석 1인칭:** 앞유리 너머로 도로가 원근으로 뻗어 있는 구도.
- **보행자(지팡이 착용자):** `proj(forward, right)` 위치에 배치. `level`에 따라 색/경고 강조.
- **"카메라 못 보는" 강조(임팩트 포인트):** 사각지대(코너·주차차 뒤)의 보행자를 하이라이트하거나 반투명 "투시"로 표현하면 V2X의 가치가 극적으로 드러난다.
- **HUD:** 거리(`distance_m`), 도달 예상(`ttc_s`), 위험 등급(`level`), 접근 속도(`closing_mps`).
- **기존 `proj` 3D 원근 엔진은 버리지 말 것** — 시점만 차량으로 바꾸면 재활용 가능하다.

## 8. 상태별 화면

| 상태 | 조건 | 화면 |
|---|---|---|
| 정상 | `t` 있음, `age_s` < 1 | 그대로 표시 |
| 갱신 지연 | 1 ≤ `age_s` < 3 | 표시하되 주의 표기 |
| **신호 없음** | `age_s` ≥ 3 | "신호 없음" (마지막 값 계속 띄우면 멈춘 화면이 실시간인 척함) |
| **대기 중** | `t === null` | "대기 중" (지팡이/차량이 아직 안 켜진 상태) |
